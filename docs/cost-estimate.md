# コスト試算

**作成日：** 2026-11-23  
**対象フェーズ：** Phase 7-4

---

## 1. 要約

- **dev 環境は、何も動かしていない間はほぼ月 $1 前後**（ホストゾーンとアラーム程度）。費用がかかるのは GameLift フリートを立てている時間だけで、検証が終わったら消す運用にしている。計画時の見積もり（月 $170〜320、[overview.md](overview.md) §6）から大きく下がったのは、VPC・NAT Gateway・CloudFront を作らず、時間課金のリソースを常設しない設計にしたため（§2）
- **本番規模（同時 1,000 セッション）では、ほとんどがゲームサーバーの費用になる。** 今の設計（c5.large 1 台に 1 セッション、台数固定）を On-Demand で動かすと **GameLift だけで月 約 $115,000**。Spot、オートスケール、1 台に複数プロセス、Graviton（転送無料）を重ねると **月 約 $1,300** まで下がる（§3.3）
- マッチメイキングと周辺（API Gateway・Lambda・DynamoDB・Cognito・CloudWatch・Route 53）は **月 約 $625**。最も大きいのは Cognito の MAU 課金（$450）で、サーバーレスの部分（API Gateway・Lambda・DynamoDB）は合わせて約 $150（§3.4）
- 本番規模の合計は、施策をすべて入れて **月 約 $2,000**（1 セッションあたり約 $0.0023、1 人 1 回のプレイあたり約 $0.0006）
- 削減が最も大きいのは、**1 台に複数プロセスを載せること**と、**第 6 世代以降のインスタンスにしてデータ転送料金を無くすこと**。どちらもまだ実施していない（§4）

## 2. dev 環境の月額

AWS dev は「本番と同じ構成」を Terraform で再現している。ただし、時間課金のものは検証のときだけ作る。

| 区分 | リソース | 月額の目安 |
|------|---------|-----------|
| 常にかかる | Route 53 ホストゾーン（raidync.com） | $0.50 |
| 常にかかる | CloudWatch アラーム 12 個（無料枠 10 個を超えた分） | $0.20 |
| 常にかかる | ドメインの登録料（.com、年払い） | 年額を月割り |
| 使った分だけ | API Gateway・Lambda・DynamoDB（オンデマンド）・CloudWatch Logs・X-Ray | 何もしなければ $0。1,000 VU の負荷テスト 1 回で $1 未満（[qa-log §15](qa-log.md)） |
| 使った分だけ | Cognito | 月 10,000 MAU まで無料。負荷テストのユーザー 1,000 人は使い回すので無料枠内 |
| 検証のときだけ | GameLift フリート（c5.large を両リージョンに 1 台ずつ）と Build 用の S3 | Spot なら 1 時間 約 $0.08（On-Demand でも約 $0.27） |
| 作らない | VPC・NAT Gateway | 作れば月 約 $60（[ADR-0005](adr/0005-no-vpc.md)） |
| 作らない | CloudFront | 配るものが無い（[ADR-0006](adr/0006-no-cloudfront.md)） |
| 必要なときだけ | Route 53 ヘルスチェック（`enable_health_checks`） | 有効にすると月 $2〜3 |

- 月 $200 の予算アラート（AWS Budgets）に対して、普段は 1% にも届かない
- この表は構成と単価から出した目安で、実際の請求額とは突き合わせていない（作業用の IAM ユーザーに Cost Explorer の権限を付けていないため）

### 計画からの差

| 計画（overview.md §6） | 実際 | 理由 |
|------------------------|------|------|
| Phase 3〜4 で月 約 $170（EC2・GameLift × 2 を常設） | フリートは検証のときだけ | 時間課金のものは常設しない。`enable_gamelift` で両リージョンをまとめて作り、まとめて消す |
| Phase 5〜6 で月 約 $320（マルチリージョン） | 待機中はほぼ $0 | セカンダリリージョンもサーバーレスで、使わなければ課金されない。Global Tables にも固定費はない |
| VPC と NAT Gateway | 作らない | Lambda も GameLift も自前の VPC を必要としなかった |

## 3. 本番規模の試算

### 3.1 前提

| 前提 | 値 | 根拠 |
|------|----|------|
| ピークの同時セッション | 1,000（4,000 接続） | プロジェクトの目標 |
| 月平均の同時セッション | ピークの 40% | 時間帯の波を仮定（夜にピーク、深夜と朝は少ない） |
| 1 セッションの長さ | 20 分 | 上限いっぱいで見積もる |
| MAU | 40,000 | ピークの同時接続 4,000 人が MAU の 10% と仮定 |
| フリートの空き | 10% | 新しいセッションをすぐ置けるように |
| 1 セッションあたりの API リクエスト | 15.6 | 1,000 VU の負荷テストの実測（ポーリング + 結果の報告） |
| 1 セッションあたりの DynamoDB | 書き込み 117 WRU、読み取り 19 RRU | 同上（チケット本体と GSI 2 本、失敗したトランザクションも含む） |
| ゲームサーバーの送信量 | 1 セッションあたり 83 MB | SESSION_STATE（4 人分の JSON で約 840 バイト）を 20Hz で 4 人に送る |
| 単価 | ap-northeast-1 | 両リージョンで分担しても、高い方の東京の単価で見積もる |
| Spot の単価 | On-Demand の 30% | Spot は変動価格。AWS の「50〜85% 安い」と、公式の計算例（約 70% 引き）から置いた |

単価は AWS の公開価格表（2026-11 取得）による。GameLift の On-Demand は c5.large が 1 時間 $0.137、c6g.large が $0.111。

### 3.2 前提から決まる量

| 項目 | 値 |
|------|----|
| 月平均の同時セッション | 400 |
| 月間セッション数 | 864,000 |
| 月間の API リクエスト | 13.5M |
| 月間のゲームサーバーの送信量 | 72 TB |

### 3.3 ゲームサーバー（GameLift）

施策を 1 つずつ重ねたときの月額。

| # | 構成 | 平均台数 | インスタンス | データ転送 | 月額 | 1 つ前からの削減 |
|---|------|-------:|-----------:|---------:|-----:|------:|
| 1 | 今の設計を On-Demand で動かす（c5.large・1 台 1 セッション・台数固定） | 1,100 | $108,504 | $6,480 | **$114,984** | — |
| 2 | Spot にする（今の Terraform の設定） | 1,100 | $32,551 | $6,480 | **$39,031** | −66% |
| 3 | オートスケールで需要に合わせる | 441 | $13,050 | $6,480 | **$19,530** | −50% |
| 4 | 1 台に 8 プロセス載せる | 56 | $1,657 | $6,480 | **$8,137** | −58% |
| 5 | Graviton（c6g.large）に変える（転送無料） | 56 | $1,343 | $0 | **$1,343** | −83% |

- **1 → 2（Spot）**: 今の Terraform の既定値。中断されても失うのは最大 20 分のセッション 1 つ（[ADR-0004](adr/0004-gamelift-managed-ec2-spot.md)）
- **2 → 3（オートスケール）**: 台数をピークに固定せず、空いているセッションの枠の割合を指標にして増減させる。費用のため検証は見送っている
- **3 → 4（1 台に複数プロセス）**: 今はゲームサーバーが固定ポート 7777 で待ち受けるため、1 台に 1 プロセス（`concurrent_executions = 1`）しか載らない。c5.large（2 vCPU・4 GB）に、4 人・20Hz・JSON のプロセス 1 つは明らかに軽すぎる。**8 は計測していない仮定**で、決めるには 1 台にプロセスを増やしながら CPU と送信の遅れを測る必要がある
- **4 → 5（第 6 世代）**: GameLift は第 6 世代以降のインスタンスでネットワーク転送を無料にしている。c5 は第 5 世代なので、72 TB 分の転送料金がかかる。ゲームサーバーは Go なので、`GOARCH=arm64` でビルドすれば Graviton で動く

1 台に載せるプロセス数で、構成 5 の月額は次のように変わる。

| 1 台のプロセス数 | 平均台数 | 月額 |
|---:|---:|---:|
| 1 | 441 | $10,573 |
| 4 | 111 | $2,661 |
| 8 | 56 | $1,343 |
| 16 | 28 | $671 |
| 32 | 14 | $336 |

### 3.4 マッチメイキングと周辺

| サービス | 量（月） | 月額 |
|---------|---------|-----:|
| API Gateway（REST） | 13.5M リクエスト | $57 |
| Lambda（arm64・256 MB） | 26.9M 回・208K GB 秒 | $5 |
| DynamoDB MatchmakingTickets | 101M WRU・16M RRU | $74 |
| DynamoDB Global Tables | 9.5M WRU + 同量のレプリケーション | $14 |
| Cognito（Essentials） | 40,000 MAU | $450 |
| CloudWatch Logs | 11.5 GB | $9 |
| CloudWatch メトリクス・アラーム・ダッシュボード | 30 メトリクス・12 アラーム・1 枚 | $13 |
| Route 53 | ホストゾーン 1・レイテンシークエリ 3.5M | $3 |
| **合計** | | **$625** |

- **サーバーレスの部分は、トラフィックに比例して安い。** API Gateway・Lambda・DynamoDB を合わせても、1 セッションあたり約 $0.00017
- **Cognito が最も大きい。** MAU の課金は遊んだ回数ではなく人数で決まるので、ゲームのような「多くの人がたまに遊ぶ」形では重くなる
- Lambda の呼び出しは API 1 回につき 2 回（authorizer + 本体）。dev では挙動を追いやすくするため authorizer の結果をキャッシュしていない

### 3.5 合計

| 区分 | 今の設計（構成 2、Spot のみ） | 施策をすべて入れた場合（構成 5） |
|------|---:|---:|
| ゲームサーバー | $39,031 | $1,343 |
| マッチメイキングと周辺 | $625 | $625 |
| **月額** | **約 $39,700** | **約 $2,000** |

## 4. 削減施策

### 実施済み

| 施策 | 効果 | 関連 |
|------|------|------|
| VPC と NAT Gateway を作らない | 月 約 $60 の固定費が無い | [ADR-0005](adr/0005-no-vpc.md) |
| CloudFront を作らない | 中身の無い CDN の費用が無い | [ADR-0006](adr/0006-no-cloudfront.md) |
| GameLift フリートは検証のときだけ作る | 唯一の時間課金リソースを常設しない。両リージョンを 1 つのフラグで作り、1 つのフラグで消す | `enable_gamelift` |
| GameLift は Spot を既定にする | 本番規模で −66%（§3.3 の 1 → 2） | [ADR-0004](adr/0004-gamelift-managed-ec2-spot.md) |
| MatchmakingTickets をレプリケーションしない | 書き込みが最も多いテーブルのレプリケーション料金（本番規模で月 約 $72）が無い | [ADR-0002](adr/0002-region-local-tickets.md) |
| DynamoDB はオンデマンド | 待機中は $0。容量の見積もりがいらない | `modules/dynamodb` |
| Lambda は arm64 | x86 より計算の単価が 20% 安い | `modules/lambda` |
| ログの保持は 7 日 | ログの保管料が積み上がらない | `log_retention_days` |
| トレースは 5% のサンプリング、索引付けは 1% | Span の取り込みと索引の費用を抑える。負荷テストのときだけ変数で全件に切り替える | [ADR-0008](adr/0008-opentelemetry-tracing.md) |
| ヘルスチェックは必要なときだけ | 月 $2〜3 を普段は払わない | `enable_health_checks` |
| 負荷テストのユーザーを使い回す | 毎回作ると 1 回で 1,000 MAU。20 回で約 $150 になるところを、無料枠内に収める | [qa-log §15](qa-log.md) |
| ローカルファースト | LocalStack・同居ハーネス・Jaeger で検証してから AWS に出す。AWS へのデプロイの回数そのものを減らす | `docker/` |

### 未実施（本番に向けて、効果の大きい順）

| 施策 | 効果（本番規模） | やること |
|------|----------------|---------|
| 1 台に複数プロセスを載せる | GameLift の台数が 1/8（8 プロセスの場合） | ゲームサーバーの待ち受けポートを固定せず、起動時の引数で受け取って GameLift に報告する。1 台に載せられる数を負荷試験で決める |
| 第 6 世代以降（Graviton など）に変える | データ転送 月 約 $6,500 → $0、インスタンス単価も約 2 割安い | arm64 でビルドし、`ec2_instance_type` を変える |
| オートスケール | 台数がピーク固定から平均に（−50%） | 空いているセッションの枠の割合を指標にしたターゲット追跡。台数は Terraform の対象外なので、スケーリングポリシーで管理する |
| Cognito のプランを見直す | Lite なら月 約 $450 → $165 | 使う機能（メールとパスワード、任意の TOTP）が Lite で足りるか確かめる |
| authorizer の結果をキャッシュする | Lambda の呼び出しがほぼ半分 | `authorizer_result_ttl_in_seconds` を 300 秒などにする。効果は月数ドルと小さい |
| SESSION_STATE をバイナリにする | 第 5 世代のままなら転送料金が数分の 1 | 第 6 世代に移れば転送は無料なので、優先度は低い |

On-Demand へのフォールバック（[ADR-0004](adr/0004-gamelift-managed-ec2-spot.md)）は費用を下げる施策ではなく、可用性のための施策。入れると Spot が足りない時間だけ On-Demand の単価がかかる。

## 5. 試算の限界

- **Spot の単価は仮定。** 実際は時間と在庫で変わる。On-Demand の 50%（AWS が示す節約の下限）なら、構成 5 のゲームサーバーは約 $2,200 になる
- **データ転送の単価は、AWS の料金ページにある最初の段の値（$0.09/GB）。** 東京の単価は確かめていない。構成 5 は転送無料なので影響しない
- **1 台に載せるプロセス数は計測していない。** §3.3 の表で幅を示した
- **1 セッションあたりの API リクエストは多めに出ている。** 負荷テストでは、マッチの取り合いのせいで成立までのポーリングが増えている（[負荷テスト結果 §8](load-test-results.md)）。ただし API の費用は全体の数 % なので、合計への影響は小さい
- **月平均 40% と MAU 40,000 は仮定。** MAU が 2 倍になれば Cognito は約 $1,050 になる
- **リージョン間の単価差と、リージョンごとのフリートの空きは無視した。** 東京の単価で一律に計算したので、us-east-1 の分だけ実際より高めになる

## 6. 試算の作り直し方

前提と単価は `scripts/cost_estimate.py` の先頭にまとめてある。値を変えて実行すると、§3.2〜§3.4 の表が Markdown で出力される。

```bash
python scripts/cost_estimate.py
```
